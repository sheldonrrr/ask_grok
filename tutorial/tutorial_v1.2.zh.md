## 简介

Ask AI Plugin 让你就 calibre 书库里的书向多种 AI 提问（OpenAI、Anthropic、Gemini、SpaceXSI、DeepSeek、Kimi、Nvidia、Perplexity、OpenRouter、Ollama 等）。

可以做的事：
- 就一本或几本选中的书提问
- 在插件里阅读 EPUB（EPUB 阅读器），就选中的文字提问
- 用自然语言搜索整个书库（AI 搜索）
- 并排比较两个 AI 的回答
- 把对话导出为 PDF

多数云端 AI 需要 API Key。Nvidia 的免费通道装好即可使用。

说明：本插件由 Ask Grok 改名而来，因为支持的不只是 Grok。

## 为什么需要 API Key

ChatGPT Plus 或 Gemini 的订阅不能直接用在这个插件里。

AI 公司把服务分成两类：
- 面向个人的订阅：用于他们自己的网站或 App
- API Key：用于开发者和本插件这类工具

这是两套计费。ChatGPT Plus 订阅在这里用不了。

不一定要付费。下面有免费选项。

## 免费 API Key

**默认：Nvidia AI Free（无需设置）**
- 费用：免费
- 设置：没有。安装后即可使用
- 默认模型：`nvidia/nemotron-3.5-lightning-30b-a3b`（较小、较快，可在配置里更换）
- 限制：共用免费额度，高峰时可能不稳定
- 说明：这是插件开发者维护的免费服务。若要更稳定或更高额度，用下面的选项。
- 说明：提交的内容可能被用来分析插件是否稳定、是否可用，请谨慎使用。在意隐私就不要用这项免费服务。开发者不会出售或利用用户隐私牟利。Nvidia 也可能将其免费额度用于数据分析。

选项 1：Nvidia（更稳定）
- 费用：新账号有免费额度（有速率限制）
- 插件中的默认模型：`nvidia/nemotron-3-nano-30b-a3b`
- 限制：大约每分钟 40 次（视 Nvidia 方案而定）
- 设置：打开 https://build.nvidia.com/ 并注册
- 取得 API Key，粘贴到插件的 Nvidia AI 配置

选项 2：OpenRouter
- 免费模型：https://openrouter.ai/models?q=free
- 获取 Key：https://openrouter.ai/settings/keys

选项 3：Ollama（本地，无需联网）
- 费用：一直免费
- 隐私：在你的电脑上运行，内容不发出去
- 设置：从 https://ollama.com/ 下载并安装
- 在终端运行：ollama pull llama3.2
- 在插件里选择 Ollama，不需要 API Key

## 安装

方法 1（推荐）：
1. 打开 calibre
2. 进入 首选项 -> 插件 -> 获取新插件
3. 搜索 “Ask AI”（作者：Sheldon）
4. 点击安装
5. 重启 calibre

方法 2（手动）：
1. 从 https://www.mobileread.com/forums/showthread.php?p=4547077 下载
2. 进入 首选项 -> 插件 -> 从文件加载插件
3. 选择 .zip 文件
4. 重启 calibre

## 第一次设置 AI

1. 从 Ask AI Plugin 菜单打开**配置**
2. 点击**添加 AI**
3. 选择服务商，输入 API Key，然后加载并选择模型
4. 点击**添加**
5. 询问是否设为**默认 AI** 时，选**是**或**否**
   - 是：之后的提问默认使用这个 AI
   - 否：保持当前默认（例如 Nvidia Free）

之后可以在配置里的**默认 AI**下拉框随时更改。

### 管理已配置的 AI

用**管理已配置的 AI** 编辑、删除或查看已经添加的 AI。在列表中双击一行即可打开。

## 如何使用

1. 在 calibre 里选中一本或多本书
2. 打开提问窗口：
   - 点击工具栏上的 Ask AI Plugin，或
   - 使用全局快捷键（默认 Ctrl+K）
3. 输入问题
4. 点击发送（或 Ctrl+Enter / Mac 上为 Cmd+Enter）

插件会自动带上书籍信息，不必再输入书名或作者。

### 用 Perplexity（Sonar）查资料

需要带来源的回答时，可以用 Perplexity。

若返回引用或搜索结果，插件会在回答末尾附上纯文本的 “Citations” / “Search Results”，并带上完整网址，方便复制。

## EPUB 阅读器（新）

- 目前 Ask AI 支持直接打开窗口阅读 EPUB 文件，并且支持边阅读边询问。
- 与 calibre 官方的区别：AI 服务调用的是 Ask AI 插件里已经配置好的设置，整体使用了更现代的交互。
- 为什么要这样做？目前 calibre 官方阅读器里的 AI 交互难用，Viewer 里行高的配置过于复杂，想要修改必须通过 GitHub 开源的方式推进，过于繁琐。
- 目前 Ask AI 内置的 EPUB 阅读器（也叫 Read & Ask）以最小的产品形态满足最基本的需求：读书时直接圈选文字后询问 AI。同时支持提示词配置和基本的教程说明。

## AI 搜索

AI 搜索可以用自然语言搜索整个书库，不必先选书。

### 如何使用 AI 搜索

**打开 AI 搜索**：
- 在插件菜单点 “AI 搜索”，或
- 使用快捷键 Ctrl+Shift+L，或
- 不选任何书，直接打开提问窗口

**这样问你的书库**：
- “有没有关于 Python 编程的书？”
- “给我看看 Isaac Asimov 的书”
- “找关于机器学习的书”
- “我有哪些科幻书？”

**打开回答里的书**

AI 会根据书库信息推荐书。点击回答里的书名即可打开。

**更新书库索引**（建议）：
- 打开 配置 -> 搜索
- 点击“更新书库数据”，为书库中**全部书籍**建立标题和作者索引
- 增删书籍后再运行一次

### 功能

- **自然语言**：用平常的话问，不需要特殊语法
- **全书库**：索引并搜索整个 calibre 书库（精简信息：书号、书名、作者）
- **语义匹配**：AI 能按语境找到相关的书
- **点击打开**：在结果里点击书名直接打开
- **大量选中时的提示**：选中超过 50 本时，提问会建议改用 AI 搜索，而不是把很长的书籍信息塞进提示词

### AI 搜索提示

- 把想找的内容说具体
- 可以问题材、作者、主题或任何书籍信息
- 书库信息整理得越清楚，效果越好
- 要在全书库里找书，用 AI 搜索，不必手动选中成千上万本书
- 要深入比较几本书，选中大约 30 本以内即可

## 快捷键

快捷键可在 calibre 里完全自定义。

如何修改：
1. 打开 calibre
2. 进入 首选项 -> 快捷键
3. 搜索 “Ask AI”
4. 修改需要的快捷键

常用快捷键（默认）：
- Ask AI：提问（全局）：Ctrl+K
- Ask AI：EPUB 阅读器（阅读并提问）：Ctrl+Shift+V（macOS 为 Cmd+Shift+V）
- Ask AI：打开配置：F2
- Ask AI：AI 搜索：Ctrl+Shift+L
- Ask AI：发送（对话框内）：Ctrl+Enter（macOS 为 Cmd+Enter）
- Ask AI：随机问题（对话框内）：Ctrl+Shift+R（macOS 为 Cmd+Shift+R）

若已在 calibre 里改过快捷键，以你的设置为准。

## 随机问题

1. 点击随机问题（或 Ctrl+Shift+R / Cmd+Shift+R）
2. AI 会给出一个问题

提示词在 配置 -> 提示词 -> 随机问题提示词 中修改。

## 提示词

提示词页可从工具栏菜单或配置打开，用来调整发给 AI 的内容。

### 角色设定

写下你的研究背景和目标。这段文字会加在每次发给 AI 的提示词前面。

例子：
- “我是文学教授，关注叙事技巧和文本分析。”
- “我在研究 19 世纪欧洲史，尤其是政治运动。”
- “我是学生，希望得到适合初学者的简单解释。”

写得越具体，回答通常越贴近你的需要。

提示：
- 写下你的领域或职业
- 说明你的程度（入门、熟练等）
- 说明你最关心哪一方面

### 提示词模板

三个可自定义的模板：

1. **单书提示词**：问一本书时使用
   - 可用变量：{title}、{author}、{publisher}、{pubyear}、{language}、{series}、{query}

2. **多书提示词**：问多本选中的书时使用
   - 可用变量：{books_metadata}、{query}

3. **随机问题提示词**：生成随机问题时使用
   - 可用变量：{title}、{author}、{language}

### 使用界面语言

打开后，插件会加上一条说明，请 AI 用当前插件语言回答。适合希望回答语言跟界面一致、而不是跟书籍语言一致的情况。

### 阅读并提问

阅读并提问在这个页面有自己的提示词设置。

### 恢复默认

点击“将提示词恢复为默认”，恢复全部提示词和相关设置。

## 其他功能

- 并行比较：在配置里把并行 AI 面板设为 2，即可并排比较不同 AI 的回答
- 历史：对话会自动保存，点击历史查看以往问答
- 导出 PDF：点击导出 PDF 保存对话，默认文件夹在 配置 -> 导出设置

## 配置

常规设置：
- 切换语言
- 窗口大小
- 并行 AI 面板：设为 2 即可并排比较
- 请求超时：等待 AI 回答的时间（默认 120 秒）
- 自定义提示词长度：可选的进阶限制（见下一节）

AI 服务设置：
- **添加 AI** / **管理已配置的 AI**：添加或编辑服务商
- **默认 AI**：提问默认使用哪一个
- 添加之后可以立刻设为默认
- 每个服务商：API Key、Base URL、模型、是否流式输出
- Kimi：按你的 Key 选择国际或中国大陆

搜索页：
- AI 搜索说明、隐私提示，以及**更新书库数据**（全书库索引）

提示词页（单独一页，便于管理）：
- 角色设定：写出研究背景和目标，让回答更贴近你
- 自定义单书、多书或随机问题的提示词
- 使用界面语言：让 AI 用插件语言回答

导出设置：
- 设置 PDF 的默认保存位置

## 自定义提示词长度

插件会限制单次发给 AI 的文字量，避免提示词过长导致超时或难懂的错误。

### 默认限制（多数人不用改）

除非碰到长度限制，或本地模型上下文很大，否则不必修改。

| 模式 | 默认上限 |
|------|----------------|
| 单书 | 128,000 字符 |
| 多书（选中的书） | 256,000 字符 |
| AI 搜索（全书库索引） | 使用精简格式，见搜索页 |

若提示词过长，插件会说明当前长度、上限、选中了多少本书，并建议全书库的问题改用 **AI 搜索**。

### 何时使用自定义上限

只有确定模型支持更大上下文时才打开，例如 **Ollama** 已把模型的 `num_ctx` 设为 128k。

不要为了“塞进去”而手动选中成千上万本书再提高上限。请改用 **AI 搜索**。自定义上限是进阶备用，不是搜索大书库的主要办法。

### 如何打开

1. 打开 配置 -> **常规**
2. 勾选**自定义提示词长度上限**
3. 填写**最大提示词长度**，单位是字符（建议默认 524288）
4. 点击**保存**

大致换算：1 token 约 3–4 个字符。使用 Ollama 时，还要在模型设置里配置 `num_ctx`。

### 多本书时的行为

- **30 本以内**：使用较完整的信息（书名、作者、出版社等），便于深入比较
- **超过 30 本**：每本书改为一行精简信息
- **超过 50 本**：提问会提议自动改用 **AI 搜索**

## 故障排除

问题过长 / 提示词过长：
- 问整个书库：使用 **AI 搜索**（不选书），或在选中 50 本以上时接受切换
- 比较多本书：30 本以内用详细信息；更多时自动改为精简格式
- 书库很大时，索引可能在上限处被截断。需要的话在常规设置里打开**自定义提示词长度上限**（建议 524288）
- 看错误说明：里面有当前长度、上限和建议做法

请求失败：
- 检查网络
- 确认 API Key 正确
- 换一个 AI 服务商

API Key 无效：
- 整段复制，不要带空格
- 确认 Key 未过期
- SpaceXSI：使用 console.x.ai 的 Key，不是 x.com
- Kimi：平台要和 Key 一致（国际或中国大陆）

Ollama 无法使用：
- 确认 Ollama 已安装并在运行
- 拉取模型：ollama pull llama3.2
- 查看模型：ollama list
- 确认服务：ollama serve

## 隐私

会发给 AI 的内容：
- 书籍信息（书名、作者、出版社、日期、语言）
- 你的问题
- 你的角色设定（若已启用）
- 你自定义的提示词

不会发送：
- calibre 的标签、注释或评论
- 阅读进度
- 个人资料

API Key 的保存：
- 保存在你的电脑上
- 不会发给第三方
- 位置：calibre 配置目录/plugins/ask_ai_plugin.json

若要尽可能保护隐私：使用 Ollama（在本地运行，内容不发出去）。

## 提示

1. 可以先问：“这本书在你的训练数据里吗？”若 AI 说没有，它能提供的帮助会比较有限。
2. 用并行面板比较不同 AI。
3. 问题写具体，回答通常更好。
4. 把角色设定写清楚，回答会更贴近你。
5. 需要出处的资料问题，用 Perplexity。
6. 用 AI 搜索在书库里找书，不必一本本翻。
7. 若出现“问题过长”，改用 AI 搜索、使用精简模式（30 本以上），或为很大的书库提高自定义上限。
8. 添加新的 AI 后，若希望下次提问用它，设为默认。
